# 申し送り: DNCL の表記を共通テスト仕様に合わせる

作成: 2026-07-30 / 作成者: Claude（評価担当） / 実施者: Gemini

## この作業を出す理由（結論）

DNCL エミュレータ（`dncl/`）を評価したところ、**制御構造や配列・関数といった中核ロジックは正しく動いている**が、
**表記が旧DNCL（情報関係基礎）寄りで、現行の共通テスト「情報Ⅰ」の表記と食い違っている**ことが判明した。

生徒が教科書どおりに書くと動かないため、**このままでは「共通テスト対策」として公開・宣伝できない**。
中身は良いので、表記を合わせれば胸を張って出せる状態になる。

## 現状の評価（実測。ここは信用してよい）

**正しく動くことを確認済み**（`dncl/verify_problems.js` と独自検査）:
- for / while / if / else / else-if の連鎖 / ループ内の if / else の中の if（深いネスト）/ ループを抜ける
- 配列（リテラル初期化・参照・代入・2次元）、関数（定義・呼び出し・返り値）
- バブルソートが54ステップで正しくソートされる
- 収録済み14問の模範解答がすべて正常実行
- ステップ実行UI（1行ずつ進む/戻る/再生）と変数スナップショット
- 誤配置へのアドバイス（初期化がループ内にある等）

→ **これらを壊さないことが最優先**。作業はすべて「追加（両対応）」で行い、既存の書き方も動くまま残す。

## 直すもの（優先度順）

**検証は `node dncl/test_notation.js` で行う。現在 9成功／18失敗。全部 OK にするのがゴール。**

対象ファイルは原則 `dncl/dncl-interpreter.js` のみ（`convertLineToJS` と `translateExpression`、
`run` 内サンドボックスの `_print`、`translateError`）。

### 1. 出力の関数形式 `表示する(...)` に対応（最重要）

公式は **`表示する("平均点は", heikin)`** の関数形式。現状は `... を表示する` の後置形式しか解釈できず、
`表示する("こんにちは")` は「変数『表示する』が定義されていません」というエラーになる。

- `convertLineToJS` に `/^表示する\s*\((.*)\)$/` のパターンを追加し、`_print(<引数>)` に変換する
- サンドボックス内の `_print(value)` を **可変長引数** `_print(...values)` にし、
  **引数を区切りなしで連結**して1行として出力する（公式例「平均点は82」の形）
- 配列が渡されたときの `[1, 2]` 形式の整形は現状の挙動を維持する
- **`... を表示する` も従来どおり動かす**

### 2. 論理演算子 `and` / `or` / `not` に対応

公式は `and` `or` `not`。現状は「かつ」「または」のみで、「でない」は未対応。

- `translateExpression` で `\band\b`→`&&`、`\bor\b`→`||`、`\bnot\b`→`!` に置換する
  - 単語境界（`\b`）を使うこと。`band` や `notfound` のような変数名の中を書き換えないため
- 「かつ」「または」は残す。可能なら「〈式〉 でない」→ `!(〈式〉)` も足す

### 3. 2次元配列のカンマ添字 `A[i,j]` に対応（**危険度が高い**）

公式は `Gyoretu[3,2]` のカンマ区切り。現状はJS流の `A[1][2]` のみ。

**`A[1,2]` は JS のカンマ演算子として評価されるため、エラーにならず `undefined` や誤った要素を返す。**
学習ツールとして、黙って誤答を返すのは最悪の挙動なので必ず塞ぐこと。

- `〈識別子〉[〈式〉,〈式〉]` を `〈識別子〉[〈式〉][〈式〉]` に変換する
- **配列リテラル `A = [1, 2, 3]` を壊さないこと**（`[` の直前が識別子かどうかで区別する）
- `A[0,1] = 99` の代入側でも効くこと
- `A[1][2]` も従来どおり動かす

### 4. 整数除算 `÷` に対応

公式は整数除算に `÷`、通常の除算に `/`。現状 `÷` は構文エラー。

- `X ÷ Y` を `Math.floor(X / Y)` に変換する。括弧つきの式（`(10 + 4) ÷ 3`）でも正しく動くこと
- ついでに全角の `＊`→`*`、`／`→`/`、`％`→`%`、`×`→`*` も正規化しておくと、生徒の打ち間違いを吸収できる
- 既存の `〜 の整数部分` は残す

### 5. else if の語形 `そうでなくもし` に対応

公式は「そうでなくもし」。現状は「そうでは**なく**もし」（「は」が入る）のみ。両方受け付けるようにする。

### 6. エラーメッセージの取りこぼしを修正

`translateError` の判定が大文字小文字を区別しているため、`Invalid or unexpected token`
（先頭が小文字の `unexpected`）が英語のまま生徒に表示される。

- 判定を大文字小文字を無視する形にする
- `Invalid or unexpected token` 系には「使えない記号が含まれています。全角の記号（×、÷、≠ など）や
  全角スペースが混じっていないか確認してください」といった日本語の説明を返す

### 7. カードと問題文の表記見直し（別作業・上記の後で）

`dncl/problems.js` の14問は「〜 を表示する」「かつ」で書かれている。
1〜6 を両対応にしたうえで、**問題文・カードの表記を公式（`表示する(...)`・`and`）に寄せる**かは
方針判断が必要なので、いったん保留。作業する場合は `verify_problems.js` が通り続けることを確認する。

## 作業の進め方（守ってほしいこと）

1. **`node dncl/test_notation.js` を全部 OK にする**（現在 9/27）
2. **`node dncl/verify_problems.js` が引き続き「成功14件・失敗0件」であることを確認する**（回帰チェック）
3. 変更は `dncl/dncl-interpreter.js` に集約する。UI（`app.js`）には手を入れない
4. **実装していないことを「対応した」と書かない**。テストで確かめられることだけを報告する
5. ファイルは **UTF-8（BOMなし）** で保存する

## 補足: 公式表記の要点（出典つき）

出典: https://note.com/toppakou/n/n08dfe37acc78 （共通テスト用プログラム表記／新DNCL の解説）

| 項目 | 公式の書き方 |
|---|---|
| 代入 | `=`（旧DNCL の `←` から変更された） |
| 比較 | `==` `!=` `>` `>=` `<=` `<`（**`≠` `≧` は使わない**） |
| 乗算・除算 | `*` / `/` |
| 整数除算・剰余 | `÷` / `%` |
| 出力 | `表示する("こんにちは")`、`表示する("平均点は", heikin)` |
| 論理演算 | `and` `or` `not` |
| 条件分岐 | `もし〜ならば` / `そうでなくもし` / `そうでなければ` |
| 繰り返し | `〈条件〉の間繰り返す` / `〈変数〉を〈初期値〉から〈終了値〉まで〈差分〉ずつ増やしながら繰り返す` |
| 配列 | 1次元 `Tokuten[2]`／2次元 `Gyoretu[3,2]`。添字は0始まりと1始まりのどちらもあり、問題文で指定される |
