## 1. ねらいと非目標

**ねらい**: 共通テスト「情報I」で確実に出る次の3点を、操作して体感できるようにする。

1. 標本化→量子化→符号化の3段階が **順番に** 起こること（用語と順序の問題が出る）
2. 標本化周波数と量子化ビット数を変えると、**復元した波のずれ（劣化）とデータ量が
   同時に動く**こと（トレードオフの理解を問う問題が出る）
3. データ量の計算: 標本化周波数 × 量子化ビット数 × 時間 × チャンネル数（計算問題が出る）

**非目標**（やらないこと・後続に回すこと）:

- 実際の音声の録音・再生（Web Audio API）。**M1では音を鳴らさない**。
  鳴らすと「耳で分かった気になる」が、試験で問われるのは図と数値の対応。
  外部入力（マイク）は権限・プライバシーの論点も持ち込むので入れない
- 標本化定理の定量的な扱い（2倍の周波数、の「なぜ」）。折り返しの現象は
  「標本が粗いと別の波に見える」という体験としてだけ見せる
- 画像のデジタル化・文字コード・圧縮。同じ器（後述のモード構造）に後から足す

## 2. 中核のレンズ: 「1標本ずつ」

dncl の「1行ずつ」ボタンに相当する操作で、1標本ごとに次の3拍を進める:

```
拍1 標本化   その時刻の波の高さを読む       （波の上に点が打たれる）
拍2 量子化   いちばん近い段階に丸める       （点が段階線へ吸い付き、ずれが赤く残る）
拍3 符号化   段階番号を2進数にして並べる     （右のビット列に 011 のように追記される）
```

3拍 × 標本数を進めきると、階段状の「復元した波」が元の波に重なって完成する。
**元の波・復元した波・ずれ（量子化誤差）が同じ画面に同時に見える**ことがこのアプリの
すべてで、つまみ（標本化周波数・ビット数）を変えた瞬間に三者が動き直す。

dncl と同じく **自動再生（実行）と1歩ずつの両方**を持つ。速度スライダーも同じ。

## 3. 画面構成

dncl の3ペイン構成（左=課題 / 中=操作対象 / 右=結果）を踏襲する:

```
┌ヘッダー: モード切替（しくみ編 / 演習編）・課題セレクタ────────────┐
├─左: 課題文とつまみ──┬─中: 波形ビュー──────┬─右: 数値ビュー────┤
│ 課題の説明           │ SVG:                  │ 標本の表:          │
│ 標本化周波数 [つまみ] │  ・元の波（曲線）      │  #  時刻 実値 量子化 2進 │
│ 量子化ビット数[つまみ]│  ・標本点と段階線      │  0  0ms  0.72  6   110 │
│ （課題により固定）    │  ・復元した階段        │  1  1ms  0.31  2   010 │
│                     │  ・誤差の赤い縦線      │ ビット列: 110010...     │
│                     │                      │ データ量: 24bit = 3byte │
└─────────────────┴─[実行][◁ 1標本 ▷][速度]─┴──────────────────┘
```

- 波形は **SVG**（chem・dncl と同じ技術選択。ビルド不要・録画モードと相性がよい）
- モバイルは**縦積み**で成立させる（dncl のシート方式は使わない。dncl はカード列が
  縦に長く操作系が画面外へ出るためシートが必要だったが、こちらは波形と数値が
  1画面の高さに収まる）
- 段階線（量子化レベル）は 2^ビット数 本。ビット数つまみを動かすと本数が変わる

## 4. モード構成

dncl の「構文学習編 / 問題演習編」に対応する2部構成:

**しくみ編**（見て理解する。M1）
1. 標本化とは — 周波数つまみだけ操作可。粗くすると波が別物になるのを見る
2. 量子化とは — ビット数つまみだけ操作可。段階が減ると誤差が増えるのを見る
3. 符号化とは — 1標本ずつでビット列が育つのを見る
4. 3段階を通しで — 両つまみ自由。データ量の式が画面に出る

**演習編**（計算して答える。M2）
- 共通テスト型の計算問題。例: 「標本化周波数 4kHz・量子化 8bit・モノラルで
  10 秒間録音すると何 byte か」。数値入力欄＋機械採点
- dncl のハードモード（穴埋め input）の作りを流用する。入力の正規化は
  dncl の normalizeInputText と同じ関数を使う（全角数字・カンマ対応）

## 5. データ構造

dncl の problems.js と同じ思想（データを足すだけで課題が増える）で `lessons.js` を置く:

```js
const lessons = [
  {
    id: "sampling_basics",
    title: "1. 標本化 — 波を一定間隔で読む",
    description: "…",
    wave: { type: "sine", freq: 2, amp: 0.8 },   // 元の波（種類＋パラメータで決める）
    controls: { sampleRate: [2, 16], bitDepth: null }, // null は固定（この課の操作対象でない）
    fixed: { bitDepth: 4 },
    narratives: { sample: (s) => `時刻 ${s.t}ms の高さ ${s.raw} を読み取った`, … },
    explanation: "…"
  },
  …
];
const exercises = [
  {
    id: "data_size_1",
    given: { sampleRate: 4000, bitDepth: 8, seconds: 10, channels: 1 },
    ask: "bytes",            // 何を答えさせるか
    answer: 40000,           // 機械検証で式から再計算して照合する
    explanation: "…"
  },
  …
];
```

- **波は乱数にしない**（録画・テスト・解説文が再現できなくなる）。種類＋パラメータで決める
- exercises の answer は **verify スクリプトが式から再計算して照合**する。
  手計算の書き間違いを機械で止める（dncl の「模範解答を実行して検証」と同じ思想）

## 6. ロジックとUIの分離

chem の chemistry.js / dncl の dncl-interpreter.js にあたる **DOM 非依存の純ロジック**を
`digitize.js` に置く:

```
digitize.js   波の生成・標本化・量子化・符号化・データ量計算。純関数のみ
app.js        UI・SVG描画・つまみ・1標本ずつ・シート制御
lessons.js    課題データ
verify_lessons.js   全課題を digitize.js で実行し、ビット列とデータ量を検証（CLI）
rec.js        録画モード（dncl の rec.js を流用。アクション語彙は同じ）
```

`run(wave, sampleRate, bitDepth)` が全標本のトレース
`[{t, raw, level, bits}, …]` を返し、UI はそれを1拍ずつ描くだけにする。
**dncl の traceLog → renderStep と同じ構造**なので、1歩ずつ・自動再生・録画が同じ型で書ける。

## 7. 共通規約（リポジトリ既定。ここでは適用の確認のみ）

- 外部アセットゼロ（Web フォント・CDN なし）。アイコンは dncl/icons.css を共有せず
  **必要分だけ複製**する（アプリ間に依存を作らない。chem 憲章の「依存は一方向」より強く、
  info 内はアプリ間依存ゼロを保つ）
- UTF-8（BOMなし）。マウスでできることはキーボードだけでもできる
  （つまみは矢印キーで増減、1標本ずつは dncl と同じボタン操作）
- 新規ファイルの参照には `?v=1`。公開確認は使い捨てクエリで
- 録画モード互換: `?rec=` の語彙（wait/click/select/step/run…）を dncl と揃え、
  chem の収録ツールが `--base` 差し替えだけで使える状態を保つ
- コミット前に verify_lessons.js 全合格＋実機確認

## 9. 機械検査（この設計自体の検証方針）

- verify_lessons.js: 全課題について (a) トレースの標本数 = 期待値
  (b) ビット列の長さ = 標本数 × ビット数 (c) 全 level が 0..2^bit-1 に収まる
  (d) exercises の answer を式から再計算して一致 — を検査する
- 「ずれ」の検査: 復元波と元波の最大誤差が、段階幅の半分以下であること
  （量子化の実装が正しければ数学的に必ず成り立つ。壊すと即検出される）
