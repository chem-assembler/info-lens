## 見つかった問題（優先順）

### 1. 実行結果が画面外にあり「1行ずつみる」が成立していない（最重要）

組み立てエリア（top 1094）と変数モニター（top 1431）が**別画面**にある。
ステップ実行しても**変数の変化を見ながらコードを追えない**。
このアプリの中心的な価値が小画面で失われている。

**方向性**: ステップ実行中は変数モニターと出力を**画面下部に固定（sticky / ボトムシート）**して、
コードと同時に見えるようにする。chem 側で同様の課題に対し
「モバイルでは右パネルをシート化する」方式を採ったので、考え方は流用できる
（`assembler/style.css` の `body.sheet-open` 周辺）。

### 2. カード置き場と組み立てエリアが離れている

トレイ（806px）とエディタ（1094px）が離れているため、**ドラッグ＆ドロップは事実上できない**
（スクロールしながらのドラッグは無理）。

ただし **`app.js` の `handleCardTap` でタップ移動が実装済み**（トレイ↔エディタを行き来する）。
つまり操作手段はある。**問題は「タップで移動できることが伝わらない」こと**。

**方向性**: ドラッグを前提にしたUIをやめ、小画面では
- タップで移動できる旨を明示（カードに「タップで移動」のヒント、または初回のみの案内）
- トレイとエディタの距離を詰める（間の余白・見出しを圧縮）
- あるいは**タブ切り替え**（カード置き場／組み立て／結果）で1画面ずつ見せる

### 3. タップ領域が小さい操作要素が18件

特に**インデント調整ボタンが 32px**。インデント操作は必須なのに、
Apple の推奨44pt・Google の48dp を下回る。モード切替タブも33px。

**方向性**: 操作系は最低 44px を確保する。chem 側では
`.canvas-header .view-btn { min-height: 42px }` のように下限を設けた前例がある。

### 4. 本題に入るまでのスクロールが長い

問題文が top 441px。ヘッダー・タイトル・説明が縦を食っている。

**方向性**: 小画面ではヘッダーを圧縮し、問題文は折りたたみ（既定は数行だけ表示）にする。

## 既存の実装状況

- `@media (max-width: 1200px)` — 3カラム（`280px 1fr 380px`）を1カラムに
