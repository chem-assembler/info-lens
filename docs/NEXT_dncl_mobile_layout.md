## 見つかった問題（優先順）

### 1. 実行結果が画面外にあり「1行ずつみる」が成立していない（最重要）

組み立てエリア（top 1094）と変数モニター（top 1431）が**別画面**にある。
ステップ実行しても**変数の変化を見ながらコードを追えない**。
このアプリの中心的な価値が小画面で失われている。

**方向性**: ステップ実行中は変数モニターと出力を**画面下部に固定（sticky / ボトムシート）**して、
コードと同時に見えるようにする。chem 側で同様の課題に対し
「モバイルでは右パネルをシート化する」方式を採ったので、考え方は流用できる
（`assembler/style.css` の `body.sheet-open` 周辺）。

### 2. カード置き場と組み立てエリアが離れている

トレイ（806px）とエディタ（1094px）が離れているため、**ドラッグ＆ドロップは事実上できない**
（スクロールしながらのドラッグは無理）。

ただし **`app.js` の `handleCardTap` でタップ移動が実装済み**（トレイ↔エディタを行き来する）。
つまり操作手段はある。**問題は「タップで移動できることが伝わらない」こと**。

**方向性**: ドラッグを前提にしたUIをやめ、小画面では
- タップで移動できる旨を明示（カードに「タップで移動」のヒント、または初回のみの案内）
- トレイとエディタの距離を詰める（間の余白・見出しを圧縮）
- あるいは**タブ切り替え**（カード置き場／組み立て／結果）で1画面ずつ見せる

### 3. タップ領域が小さい操作要素が18件

特に**インデント調整ボタンが 32px**。インデント操作は必須なのに、
Apple の推奨44pt・Google の48dp を下回る。モード切替タブも33px。

**方向性**: 操作系は最低 44px を確保する。chem 側では
`.canvas-header .view-btn { min-height: 42px }` のように下限を設けた前例がある。

### 4. 本題に入るまでのスクロールが長い

問題文が top 441px。ヘッダー・タイトル・説明が縦を食っている。

**方向性**: 小画面ではヘッダーを圧縮し、問題文は折りたたみ（既定は数行だけ表示）にする。

## 対応結果（2026-07-30 実装ぶん）

### 1. 実行シート ✅

実行（またはステップ）を始めると `body.stepping` が付き、小画面では右ペインを画面下に固定する。

- 固定するのは **変数モニター・出力・判定バー**。「組み立てたプログラム」は
  同じ内容が上のカード列に見えているので実行中は隠す
- **「実行」ボタンとステップ操作（◁ n/m ▷）もシートへ移す**（`app.js: syncSheetControls`）。
  ヘッダーに置いたままだとコードをスクロールした時点で操作系が画面外に出て、結局動かせなかった。
  要素を移動しているだけなのでイベントは付いたまま。PC幅・実行終了時は元の並びへ戻す
- つまみ（`#sheet-toggle`）でたたむと操作帯だけの高さ（65px）になる
- **横持ち（landscape）は下ではなく右側パネル**にした。縦375pxで下に置くと
  変数モニターが44pxまで潰れて読めなかったため

副作用として直したもの:
- `#editor-list` の内側スクロールを小画面では廃止（ページと二重スクロールで
  現在行の自動スクロールが噛み合わなかった）
- `.block-card` に `flex-wrap: wrap`。ナレーション吹き出し（`width:100%`）が
  1行に押し込まれ、388px幅では **幅85px・高さ344px の柱**になっていた

計測（388×838・22ステップ全部を確認）: 現在行は毎ステップ**シートの上に完全に収まり**、
同じ画面で変数が更新される。シート内は 384px に収まりスクロールなし。

### 2. カード移動の導線 ⏸ 未着手（要相談）

**なお、この文書には「タップ移動が実装済み」とあるが、正確には `dblclick`（ダブルタップ）に
バインドされている**（`app.js: createBlockCard`）。UIの案内文も「ダブルクリック（ダブルタップ）」。
シングルタップにするか等を含めて相談したい。

### 3. タップ領域 ✅

**44px未満の操作要素は 18件 → 0件**（388×838・イージー／ハード／構文学習の各モードで確認）。

- インデントボタン 32px → 44×44
- モード切替タブ・難易度タブ・ヘッダーの各ボタンとセレクト・ステップ操作 → 最低44px
- 速度スライダー 4px → 44px（見た目の線は `::-webkit-slider-runnable-track` で細いまま）
- ハードモードの穴埋め入力欄 23px → 44px。あわせて **文字を 1rem に**
  （16px未満だと iOS Safari がフォーカス時に勝手にズームする）
- 戻るリンク・フッターのリンクも44px

**hover のないタッチ端末では、そもそもインデントボタンが見えていなかった**
（`.block-card:hover .indent-btn-group` でしか表示されない）ので、小画面では常時表示に変更。
逆にトレイ上のインデントボタンは `adjustIndent` が弾いていて無意味なので隠した（幅も浮く）。
