## 書き方（既存の問題に必ず合わせる）

`dncl/problems.js` の既存エントリ（例: `sum_1_to_n`, `coin_change`）を**雛形としてそのまま真似する**。
必要な要素は以下のすべて。**1つでも欠けると UI が壊れるか、学習体験が劣化する。**

```
{
  id: "英数字の識別子",
  title: "日本語のタイトル",
  description: "何を作るかの説明。前提（変数の初期値など）も書く",
  difficulty: "初級" | "中級" | "上級",
  initialState: { 変数名: 初期値, arrayData: 配列またはnull },
  correctBlocks: [ { id:"b1", text:"...", indent:0, isLocked:true? }, ... ],  // 正解の順序とインデント
  easyBlocks:   [ ... ],   // 正解カードのみをシャッフルした並び
  normalBlocks: [ ... ],   // easy＋ダミーカード（isDummy:true, reason:"なぜ違うのか"）
  hardBlocks:   [ ... ],   // 一部を [input_xxx] の穴埋めにしたもの（inputs で correct と placeholder を指定）
  narratives: { ブロックid: (vars) => `この行が何をするかの日本語`, ... },
  explanation: "解き方の説明。【入れ替え可能な箇所】も書く"
}
```

### 特に注意すること

1. **表記は公式（新DNCL）のみを使う**——`表示する(...)`／`and` `or` `not`／`÷`／`%`／`A[i,j]`／
   `そうでなくもし`。旧表記（`〜 を表示する`・`かつ`・`の整数部分`・`A[i][j]`）は使わない。
   **`node dncl/test_problems_notation.js` が検出するので必ず 0 件で終えること**
2. **同じ `id` のカードは全難易度で同じ text にする**（片方だけ違うと難易度で挙動が変わる）
3. **ダミーカードの `reason` は「なぜ間違いか」を具体的に書く**。
   「これでは毎回1しか足されません」のように、生徒がつまずく理由に踏み込む。
   ここが教材としての価値なので手を抜かない
4. **`narratives` は各行が何をするかを日本語で書く**（ステップ実行時に表示される）。
   変数の値を埋め込む関数形式にできる（既存の `(vars) => ...` を真似する）
5. **`initialState` と模範解答の整合**——`verify_problems.js` が模範解答を実行して
   エラーが出ないことを検査するので、初期値が足りないと落ちる
6. 難易度は**上級に偏らせない**。初級・中級を入り口として厚くする
